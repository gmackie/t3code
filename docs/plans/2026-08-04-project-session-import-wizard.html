Overview

Build a user-triggered wizard that defaults to scanning ~/, accepts a runtime-selected root such as /Volumes/dev, discovers Git repositories recursively, correlates them with native Claude, Grok Build, and Codex histories, and imports the selected projects and full session histories into T3 Code. Discovery is read-only and incremental; all matching sessions are selected by default on a review screen; execution reuses existing projects and is safe to retry.

Goals & Non-goals

Goals

  • Recursively discover real Git roots beneath a user-selected directory.
  • Stream repositories and sessions incrementally at large-corpus scale.
  • Create missing projects, reuse existing projects, and import full histories.
  • Make retries idempotent and failures local to each repository/session.

Non-goals

  • No startup/background scans.
  • No mutation of native provider history.
  • No automatic model/provider migration.
  • No symlink traversal outside the chosen root.

Milestones

  • Phase 1 — Scan safely
    Repository traversal and contracts, proven with filesystem fixtures.
  • Phase 2 — Correlate and execute
    Incremental provider discovery plus idempotent project/session import.
  • Phase 3 — Wizard UX
    Root picker, scalable review list, progress, and completion links.
  • Phase 4 — Real migration proof
    Scan /Volumes/dev, verify actual Claude sessions, then release.

Scanner rules

Default root is the server user's home directory. The client may select /Volumes/dev at runtime. Never follow directory symlinks. Prune .git, dependency directories, caches, build outputs, trash, application support, and vendored reference directories. Once a repository root is accepted, stop ordinary descent, while explicitly recognizing nested Git roots and linked worktrees through Git metadata rather than broad content traversal.

Risks & Mitigations

Risk Severity Mitigation
Home scans traverse huge or sensitive trees High Visible root, explicit start, strict pruning, cancellation, no symlink following, no writes.
Thousands of sessions overwhelm UI/server High Bounded concurrency, incremental pages, virtualized rows, provider filters.
Stale scan tokens import into wrong project High Opaque scoped tokens and server-side repository/project revalidation at execution.
Partial execution creates duplicates Medium Reuse active workspace-root matches and existing external-import identities; itemized retry outcomes.
